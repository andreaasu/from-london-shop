# Analytics

Vercel builds read `VITE_GA_MEASUREMENT_ID`, `VITE_CLARITY_PROJECT_ID`, and `VITE_META_PIXEL_ID`. Redeploy after changing a value. No SDK or database changes are needed.

Meta uses browser image-pixel requests to `https://www.facebook.com/tr/` for `PageView`, `ViewContent`, `AddToCart`, `InitiateCheckout`, and `Purchase`, through the existing consent and SPA hooks. Product events include product IDs, quantities, item prices, EGP currency, and value; Purchase uses the confirmed order total. A separate browser-local order ledger and stable event ID prevent repeat purchases independently of GA4. Requests use sanitized page paths and no HTTP referrer. No customer fields, advanced matching, automatic DOM/form events, Meta SDK, or Conversions API are used. Meta still receives normal browser network information such as the visitor's IP address. Pixel Helper may not detect this image transport; verify in DevTools Network (`facebook.com/tr`) and Meta Events Manager Test Events. Disable automatic events and automatic advanced matching in Meta Events Manager, and do not install another Meta tag through Vercel or Tag Manager. Blockers or interrupted requests can prevent delivery; the ledger records attempted sends, not Meta acknowledgements.

The compact consent notice has equally visible Accept and Decline buttons; it never blocks shopping. Privacy settings and the analytics disclosure are in the footer. Keyboard users can open settings, close with Escape, and return focus to the footer button. The choice expires after 180 days. Withdrawal reloads the page to unload tracking listeners. Cart storage remains intact. Rejected activity is never replayed after consent. Global Privacy Control and Do Not Track keep optional analytics off.

## Regional notice policy

`/api/analytics-policy` uses Vercel's edge-provided country header, not browser language, timezone, a third-party geolocation service, or precise location. Responses are private/no-store and contain only a consent-required boolean. Tracking stays off while the policy resolves unless there is an existing explicit acceptance. Unknown countries, local development, errors, and unapproved regions require opt-in. No notice appears when neither analytics ID is configured.

Set the **server-side Vercel variable** `ANALYTICS_OPT_OUT_COUNTRIES` to a comma-separated list of country codes where your business has established that these analytics may run without explicit consent, then redeploy. There is deliberately no assumed worldwide exemption: the store's applicable law, session recordings, and international transfers can impose requirements beyond a visitor's country. The EEA, UK, Switzerland and listed EU territories always require opt-in even if mistakenly included. Until an approved list is configured, unknown legal situations retain the compact notice.

Approved regions get no automatic popup: GA4 may run using analytics storage, while Clarity receives a denied storage signal and uses its cookieless behavior until explicit acceptance through footer settings. Inferred permission is never saved as an explicit choice. A saved Decline and browser privacy signals override regional defaults. Customer-content masking and admin exclusion remain unchanged. Check Clarity's current project settings and cookieless functionality before relying on full recordings/unique-visitor metrics for that mode.

Verify the policy with a fresh browser in an approved region (no popup), an opt-in region (compact notice; no tracking until Accept), and an unknown/offline region (opt-in fallback). Test saved Decline and browser GPC in both modes. An existing explicit choice suppresses repeat notices.

GA4 automatically measures users and sessions after consent. The app sends SPA `page_view`, `view_item`, `add_to_cart`, `remove_from_cart`, `begin_checkout`, and `purchase` events. Ecommerce items contain only product ID, numeric price and quantity; currency is EGP. Quantity changes send only the added/removed quantity. Purchases run exclusively after the existing order API returns a confirmed Supabase order ID, using its total (delivery is collected separately). Item prices reflect the cart snapshot. Confirmation-page refreshes never send purchases. A browser-local order-ID ledger and GA4 transaction IDs provide duplicate protection. This is browser tracking: denied consent, blockers, cleared storage, or interrupted network delivery can affect reporting; it is not an order accounting system.

## Dashboard setup

- GA4: Admin → Data streams → your web stream → Enhanced measurement. Disable automatic page views/history-based page views because the React router sends them. Disable form interactions, site search, and other automatic enhanced events so arbitrary form/link/query values cannot enter reports. Do not enable user-provided data collection. These are property settings and cannot be changed by the website code.
- Clarity: Settings → Masking → Strict is recommended as additional protection. The application root already has `data-clarity-mask="true"`, covering checkout, confirmation and customer content regardless of dashboard masking defaults. No identify API or customer fields are sent. Admin navigation stops recording; URL parameters/hashes prevent starting recordings and stop an active recorder. Never put customer details in URLs (DOM masking does not mask URLs). Configure any needed URL parameter masking in Clarity too.
- Do not add duplicate GA/Clarity tags through Vercel integrations, Tag Manager, or HTML snippets.

## Quick live verification

1. Open an incognito session with DevTools Network. Before accepting, and after rejecting, there should be no Google Analytics or Clarity script/collection requests. Accept via Privacy settings; configured scripts should load once. Missing IDs simply leave that tool disabled.
2. In GA4 Realtime (or DebugView using Google Analytics Debugger), navigate between pages, view a product, add it, change quantity, remove it and enter checkout. Confirm event names, product IDs, quantities, prices and EGP. Inspect requests to confirm URLs exclude query/hash and no email, phone, address, name or notes are included.
3. Place one test order and check one `purchase` with its Supabase order ID as `transaction_id` and its confirmed total. Refresh the confirmation page: no extra purchase. A failed order must not emit a purchase. Existing test orders create real orders and invoke the existing email flow.
4. In Clarity, check the new recording and heatmap after processing. Verify checkout inputs and confirmation/customer content are masked; admin pages should not be recorded. Then reject analytics through Privacy settings and confirm the reload stops collection.
